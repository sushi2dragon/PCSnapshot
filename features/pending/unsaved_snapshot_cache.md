# Unsaved snapshot cache (auto restore points)

Keep a rolling cache of the last 3 desktop arrangements that were *never explicitly saved*, so a "your desktop isn't saved / this arrangement will be lost" situation is always recoverable. When the instant drift check (see `is_current_state_saved`) determines the live desktop is not covered by any snapshot and the user is about to do something destructive (a clean restore), fire a **full-fidelity** background auto-capture — screenshot, browser tabs, terminal CWDs, the works — into a separate pruned ring directory (reusing the normal snapshot JSON+PNG format), oldest evicted past 3. This capture must run async / off the click, because full fidelity needs the slow signals (UI Automation, shell inspection) that the instant path deliberately skips; only bank on detected drift so we cache exactly the arrangements that would otherwise be lost. Surface the ring in Settings as "Recently auto-saved" restore points the user can promote to a real snapshot or restore from. Deferred for now — pinned here so the design isn't lost.

**Also folded in here: browser-tab / document drift detection.** The instant `is_current_state_saved` check is deliberately counts-only (per-app window counts), so it cannot see tab changes — a tab is not a window. Two sub-cases both belong to this richer path rather than the instant check: (1) *switching/opening the active tab or changing a document* shows up in the window **title**, but folding titles into the instant check risks false "not saved" from ambient title churn (unread badges, clocks, media titles) right after a capture — the original false-positive complaint — so it was declined; (2) *background tabs* change nothing observable instantly and can only be seen via the full browser-session capture. When this cache/full-capture path is built, compare captured browser-session tab sets (and optionally normalized titles) to detect tab-level drift properly.
